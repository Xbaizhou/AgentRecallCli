## Clarifications

### Session 2026-08-29

- Q: 未指定来源列表时的默认启用范围是什么? → A: 仅启用 optionalSetting 为 null 的「默认开启」来源;需要显式开启的来源不参与默认加载,必须通过来源列表显式传入(依据:计划 1.2 optionalSetting 语义「null = 默认开启」)。
- Q: 秒与毫秒混用的时间戳如何归一? → A: 统一归一为毫秒——数值 < 10^12 视为秒并乘以 1000,≥ 10^12 视为毫秒原样保留;以边界测试锁定该启发式(依据:计划 1.6 坑点表「在 adapter 里统一归一成 ms」)。
- Q: 内置来源具体定哪几个、目录约定是什么? → A: 内置 3 个——claude-cli(claude 族,目录约定 `<根>/claude/**/*.jsonl`)、codex(codex 族,目录约定 `<根>/codex/**/rollout-*.jsonl`)、workbuddy-cli(workbuddy 族,目录约定 `<根>/workbuddy/**/*.jsonl`,五项能力全 false 的只读来源,作为能力开关表达产品边界的实例);真实用户目录到根目录的映射属实现层(依据:计划 1.2/1.7「只实现 3 个来源」与 workbuddy 全 false 案例)。
- Q: 空文件、整文件损坏、重复会话标识的处理语义是什么? → A: 空文件产出消息数为 0 的会话并计入统计;整文件损坏(所有行均坏)同样产出 0 消息会话且坏行数等于总行数;同一来源出现重复会话标识时不覆盖、不合并,以文件为单位各自产出(唯一性约束留待阶段 2 存储层)。

## 用户场景与测试 *(强制)*

### 用户故事 1 - 解析合成会话目录并输出统计 (Priority: P1)

学习者把一批合成会话文件(jsonl 格式)放入一个目录,执行加载流程后,得到每个来源的会话列表与消息列表,并看到一份汇总统计:每个来源多少会话、多少消息。这是整个 mini-recall 的第一块可用产出——「磁盘文件 → 领域对象」。

**Why this priority**:没有解析层就没有后续一切(存储、索引、查询、Agent);它是其他所有故事的依赖基座。

**Independent Test**:对一个只含正常样例的目录执行加载,能得到结构正确的会话数组与统计输出,即为通过。

**Acceptance Scenarios**:

1. **Given** 一个含正常样例文件的目录,**When** 执行加载,**Then** 返回非空的已加载会话数组,每个会话包含元数据(来源、文件路径、标题、消息数)与消息列表。
2. **Given** 同一目录加载完成,**When** 查看统计结果,**Then** 能看到每个来源的会话数与消息数,且数字与文件内容一致。

---

### 用户故事 2 - 损坏数据容错与显式计数 (Priority: P1)

目录中混有「写了一半崩溃」的半行 JSON、带 BOM 的文件、空文件。加载流程必须把这些文件处理完:正常行照常解析,损坏行逐行跳过并把坏行数量显式统计出来——绝不静默吞掉,也绝不因单个文件损坏而整体失败。

**Why this priority**:容错解析是真实场景(Agent 写会话中途崩溃)的核心验收点,也是计划 1.4 明确要求的第一条验收标准。

**Independent Test**:向目录放入 1 个最后一行为半行 JSON 的文件后执行加载,正常行全部解析、坏行计数等于实际坏行数、加载过程无未捕获异常,即为通过。

**Acceptance Scenarios**:

1. **Given** 目录含 1 个最后一行为半行 JSON 的文件,**When** 执行加载,**Then** 该文件前面的正常行全部解析为消息,半行被跳过且坏行计数 ≥ 1。
2. **Given** 目录含带 BOM 的文件或空文件,**When** 执行加载,**Then** 两者都不导致加载失败:带 BOM 文件正常解析,空文件产出消息数为 0 的会话并计入统计。

---

### 用户故事 3 - 按来源过滤加载 (Priority: P2)

学习者只想加载某个(些)来源的会话(例如只看 codex),加载流程支持传入来源子集,仅遍历并解析所选来源的文件。

**Why this priority**:来源过滤是上层「只索引部分来源」行为的基础,但依赖故事 1 的解析能力先就位。

**Independent Test**:对同时含多个来源文件的目录指定单一来源加载,结果中不出现其他来源的会话,即为通过。

**Acceptance Scenarios**:

1. **Given** 目录含 A、B 两个来源的文件,**When** 指定仅加载来源 A,**Then** 结果只含 A 的会话,B 的文件完全未被解析。
2. **Given** 未指定来源子集,**When** 执行加载,**Then** 仅加载 optionalSetting 为 null 的「默认开启」来源,需显式开启的来源不出现。

---

### 用户故事 4 - 来源注册表自检不变量 (Priority: P2)

来源注册表是本阶段的灵魂抽象:每个来源以「描述符」静态注册(唯一 ID、显示名、解析格式、来源族、可选设置、五项能力开关)。注册表自带不变量自检——任何一个描述符字段缺失或非法,自检必须立刻报错。这个抽象是「自检查」的:抽象坏了,测试先红。

**Why this priority**:注册表质量决定后续阶段能否安全扩展新来源,但它可以在故事 1 交付后单独验收。

**Independent Test**:故意把某个描述符的字段改坏(删除或置非法值),运行不变量校验必须报错并列出问题,即为通过。

**Acceptance Scenarios**:

1. **Given** 注册表中任一描述符缺少必备字段或字段非法,**When** 运行不变量校验,**Then** 校验失败并指出具体来源与字段。
2. **Given** 注册表全部字段合法,**When** 运行不变量校验,**Then** 校验通过且来源 ID 无重复。

---

### 边界情况

- 文件以 BOM 开头:第一个解析单元不得因 BOM 失败(须先剥离)。
- 文件最后一行是半行 JSON:跳过该行并计入坏行,不影响前面行的解析。
- 完全空的文件(0 字节或 0 行):不产出消息,产出消息数为 0 的会话并计入统计。
- 整文件损坏(所有行均坏):产出 0 消息会话,坏行数等于总行数,不整体失败。
- 时间戳格式不统一(秒 vs 毫秒):按 FR-008 启发式归一为毫秒(< 10^12 视为秒),以边界测试锁定。
- 出现注册表中不认识的文件/目录:不崩溃,按「未知来源不处理」计数或忽略。
- 同一来源下重复会话标识:不覆盖、不合并,以文件为单位各自产出(唯一性约束留待阶段 2)。

## 需求 *(强制)*

### 功能需求

- **FR-001**:系统必须提供「来源注册表」,静态声明每个会话来源的描述符:唯一 ID、显示名、解析格式、来源族、可选设置(null 表示默认开启)、五项能力开关(实时会话、续聊、迁移、hook 同步、打开对应应用)。
- **FR-002**:系统必须支持「格式适配器」按解析格式组织;适配器必须是纯函数:输入文件全文,输出 { 会话, 消息列表 } 或 null(整体解析失败),不访问文件系统、不做目录遍历。
- **FR-003**:系统必须提供「会话加载器」:输入 { 根目录, 可选来源列表 },输出已加载会话数组;加载器是本特性中唯一允许访问文件系统的模块。
- **FR-004**:加载器必须按启用来源的目录约定遍历根目录,定位会话文件,并调用对应格式的适配器解析。
- **FR-005**:解析必须逐行容错:单行损坏时跳过该行并继续解析后续行;坏行数必须计入结果并可在统计中显式输出。
- **FR-006**:加载结果必须携带显式统计:每个来源的会话数、消息数、跳过坏行数;统计不得静默丢弃任何计数。
- **FR-007**:加载器必须支持按来源子集过滤;未指定来源列表时,默认仅启用 optionalSetting 为 null 的「默认开启」来源(见澄清 Session 2026-08-29 第 1 条)。
- **FR-008**:消息时间戳必须归一为毫秒后产出:数值 < 10^12 视为秒并乘以 1000,≥ 10^12 视为毫秒原样保留;归一启发式必须有边界测试锁定(见澄清 Session 2026-08-29 第 2 条)。
- **FR-009**:内置来源必须为 3 个——claude-cli、codex、workbuddy-cli,目录约定分别为 `<根>/claude/**/*.jsonl`、`<根>/codex/**/rollout-*.jsonl`、`<根>/workbuddy/**/*.jsonl`;其中 workbuddy-cli 五项能力全为 false,作为「能力开关表达产品边界」的只读来源实例(见澄清 Session 2026-08-29 第 3 条)。
- **FR-010**:注册表必须提供不变量自检:任一描述符缺失必备字段、字段非法或来源 ID 重复时报错,并指明具体来源与问题。
- **FR-011**:本特性的一切测试必须使用手写合成数据与临时目录;禁止读写真实 Agent 会话目录(数据安全红线)。
- **FR-012**:容错语义必须固定:空文件产出消息数为 0 的会话并计入统计;整文件损坏产出 0 消息会话且坏行数等于总行数;重复会话标识不覆盖、不合并,以文件为单位各自产出(见澄清 Session 2026-08-29 第 4 条)。

### 关键实体

- **Session(会话)**:一次 Agent 会话的元数据——来源、原始 ID、项目路径、文件路径、标题、首个提问、时间戳、消息数。
- **SessionMessage(会话消息)**:会话内一条消息——序号、角色、内容、时间戳;最小字段集为角色/内容/时间戳,token 与 trace 等扩展字段不在本阶段。
- **LoadedSession(已加载会话)**:会话元数据 + 消息列表的组装结果,是加载器的产出单元。
- **SessionSourceDescriptor(来源描述符)**:注册表的一行——声明来源的格式、族与能力开关;决定「由哪个适配器解析、去哪个目录找文件、上层能对该来源做什么」。
- **SessionSourceCapabilities(能力开关)**:五项布尔能力(实时/续聊/迁移/同步/打开应用),让上层按声明式能力决定行为而非散落的条件判断。
- **加载统计**:本次加载的量化回执——按来源的会话数、消息数、坏行数。

## 成功标准 *(强制)*

### 可度量结果

- **SC-001**:对一个含 ≥ 10 个合成文件(其中 ≥ 1 个为半行损坏)的目录执行加载:100% 的正常行被解析为消息,坏行计数与实际坏行数完全一致。
- **SC-002**:任何单个文件的损坏不导致整体加载失败——目录内全部文件都被处理(处理完成率 100%),无未捕获异常中断。
- **SC-003**:统计输出让人在 10 秒内看清「每个来源多少会话、多少消息、跳过多少坏行」,三类数字齐备。
- **SC-004**:向注册表注入任一种字段损坏(缺失/非法/重复 ID),不变量自检 100% 报错且指明问题位置。
- **SC-005**:指定单一来源加载时,其他来源文件的解析率为 0%(完全不被触碰)。
- **SC-006**:同一目录重复执行加载,两次结果完全一致(可重现性 100%)。

## 假设

- 测试数据全部为手写合成 fixtures(≥ 10 个 jsonl 样例,含正常、半行损坏、BOM、空文件四类),绝不使用真实会话数据。
- 「用户」即本项目学习者本人:通过测试与统计演示验收,无图形界面。
- 消息最小字段集为角色/内容/时间戳;更丰富的字段(token、trace、远程环境)属于后续阶段或方向性延伸。
- 具体工程约束(运行时版本、模块规范、依赖白名单、测试门禁)由项目宪法固定,在实现计划中落为技术方案,本规格只约束行为与验收。
- 本特性排除:存储与增量索引(阶段 2)、查询服务与契约层(阶段 3)、Agent 决策循环(阶段 4)、MCP(阶段 5)、评测(阶段 6)。
