# mini-recall 运行指南

> 本文所有命令均在 Windows 11 + Node v24.15.0 实测通过。目标读者:首次拿到仓库、想把它跑起来的人。

## 1. 这个项目是什么

mini-recall 是 AgentRecall v1 的复现式学习仓库:把本地 Agent 会话文件(jsonl)解析入库,提供增量索引、全文检索、CLI 交互,并以 ReAct Agent 与 MCP server 两种方式对外暴露检索能力。**不依赖任何外部服务**,一条命令都离线可跑。

## 2. 环境要求(硬性)

| 依赖 | 版本要求 | 说明 |
| --- | --- | --- |
| Node.js | **≥ 22.13** | `node:sqlite` 的 `DatabaseSync` 依赖此版本;实测 v24.15.0 |
| npm | ≥ 10(随 Node 安装) | 仅用于装依赖与跑脚本 |
| 操作系统 | Windows / macOS / Linux | 纯本地 Node 进程,无平台专属代码 |
| SQLite | **无需安装** | `node:sqlite` 是 Node 内置模块,FTS5/trigram/WAL 全部开箱可用 |
| Git | 任意较新版本 | 仅拉取代码时需要 |

## 3. 依赖关系

### 3.1 npm 依赖(宪法 IV 白名单,新增依赖须先修订宪法)

| 包 | 类别 | 用途 |
| --- | --- | --- |
| `zod` | **运行时(唯一)** | 跨边界契约校验(CLI/Agent 工具参数/MCP 调用) |
| `typescript` | 开发期 | 静态门禁 `tsc --noEmit` 与构建 `tsc -p tsconfig.build.json` |
| `vitest` | 开发期 | 测试与评测运行器 |
| `esbuild` | 开发期(仅构建) | 把 MCP server 打成零依赖单文件 CJS bundle |
| `@types/node` | 开发期 | Node API 类型 |

数据库能力来自 Node 内置的 `node:sqlite`(无第三方 ORM/驱动);LLM 调用基于内置 `fetch`。

### 3.2 模块分层(上层依赖下层,下层不感知上层)

```text
src/cli.ts(渲染层)
  ├─ src/shared/   zod 契约(SEARCH/MESSAGES/STATS)
  ├─ src/agent/    ReAct 决策循环(llm/tools/rewrite/reflect/prompt/loop)
  └─ src/core/     领域内核
       ├─ session-loader(唯一 fs 访问模块:scan 仅 stat / parse 按需解析)
       ├─ indexer(增量同步:size+mtime 快照判定,解析前跳过)
       ├─ search(FTS5 × SQL 两路求交/分页/排序)
       └─ store/(SQLite:database/schema/sessions/messages/fts)
src/mcp/          MCP server(JSON-RPC over STDIO,只读)+ db 指针
eval/             评测(A/B/C 三模式对照)
fixtures/         合成会话数据(只读知识源)
```

数据流:`fixtures/*.jsonl → loader → indexer → SQLite(+FTS5)→ search / Agent / MCP`。

## 4. 安装

```bash
git clone https://gitee.com/daytime-xie/mini.git
cd mini
npm install
```

## 5. 快速开始(约 5 分钟)

```bash
# 1) 跑通全部测试(19 个文件 118 项,含各阶段验收演示输出)
npm test

# 2) 进入交互式 REPL(首次会构建到 dist/ 再运行)
npm run cli
```

REPL 内依次执行(以仓库自带合成数据为例):

```text
> sync --rootDir fixtures          # 解析 fixtures 并增量入库(9 个会话)
> search --query FTS5 --limit 3    # 全文检索(中文/英文均可)
> messages claude-cli:sess-001 --tail 5   # 查看某会话最近消息
> stats                            # 按来源/按日分布
> quit
```

数据落在 `~/.mini-recall/`(项目自建目录,**绝不读写**真实 `~/.claude`、`~/.codex`);再次 `sync` 同一目录时,未变化的文件会被跳过(`skipped` 计数),这就是增量索引。

## 6. 命令一览(全部实测)

| 命令 | 做什么 | 产出 |
| --- | --- | --- |
| `npm run typecheck` | 静态门禁(`tsc --noEmit`),提交前必跑 | 0 错误 |
| `npm test` | 全部测试 + 各阶段验收演示 | 终端打印演示统计 |
| `npm run cli` | 构建(`tsc -p tsconfig.build.json` → `dist/`)并进入 REPL | 交互式检索 |
| `npm run build:mcp` | esbuild 打包零依赖 MCP bundle | `dist/mini-recall-mcp.cjs` |
| `npm run eval` | A/B/C 三模式评测(24 问) | `eval/report/eval-report.{json,md}` |

> 说明:不能直接 `node src/cli.ts`——源码按 NodeNext 规范用 `.js` 后缀导入 `.ts` 文件,Node 直跑无法解析;必须经 `npm run cli` 的构建产物运行(`dist/cli.js` 中导入的是真实 `.js` 文件)。

## 7. REPL 命令参考

| 命令 | 语法 | 说明 |
| --- | --- | --- |
| sync | `sync --rootDir <目录>` | 扫描目录(按来源注册表的目录约定与文件模式),增量入库;输出 indexed/skipped/removed/conflicts/errors |
| search | `search --query <词> [--source <来源>] [--project <前缀>] [--after YYYY-MM-DD] [--before YYYY-MM-DD] [--limit N] [--sort time\|relevance]` | 关键词(FTS5)与结构化过滤求交;非法参数被字段级拒绝 |
| messages | `messages <sessionKey> [--tail N]` | 查看某会话最近 N 条消息(保持原始顺序) |
| stats | `stats` | 按来源、按日的会话数分布 |
| help / quit | `help` `quit`(或 `exit`) | 帮助 / 退出 |

## 8. 作为 MCP server 接入宿主(Claude Code 等)

1. 构建 bundle:`npm run build:mcp`(产物零运行时依赖,可拷到任意目录运行)。
2. 先运行过一次 `npm run cli` 并 `sync`——主程序会把库路径写入 `~/.mini-recall/db-path`,server 靠这个指针定位库(也可用环境变量 `MINI_RECALL_DB` 覆盖)。
3. 在宿主的 MCP 配置中注册:

```json
{ "mcpServers": { "mini-recall": { "command": "node", "args": ["<绝对路径>/dist/mini-recall-mcp.cjs"] } } }
```

4. server 行为:STDIO 上按行分隔 JSON-RPC 2.0,提供 `initialize` / `tools/list` / `tools/call`;**只读四件套** `search_sessions` / `get_messages` / `list_sources` / `now`;stdout 只承载协议消息,日志走 stderr;库以只读模式打开(WAL 保证与写进程并发互不阻塞)。

手工验证(不经宿主):

```bash
printf '{"jsonrpc":"2.0","id":1,"method":"initialize"}\n{"jsonrpc":"2.0","id":2,"method":"tools/list"}\n{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"search_sessions","arguments":{"query":"FTS5"}}}\n' | node dist/mini-recall-mcp.cjs
```

## 9. 评测

```bash
npm run eval
```

同一数据集(24 问,fixtures 为唯一知识源)跑三模式对照:A 直接关键词检索 / B 查询改写后检索 / C 完整 Agent 循环,输出 recall@5、MRR、平均工具调用、token、延迟与无命中诚实率,报告落盘 `eval/report/eval-report.{json,md}`。当前实测结论:B 的改写把「词汇失配/时间窗」类问题的 recall@5 从 50% 提到 100%。评测全程用 MockLlm(零 token、确定性);接入真实 LLM 见下。

## 10. 二次开发指引

- **门禁**:每任务/每提交前 `npm run typecheck` + `npm test` 必须全绿;测试文件与源码同目录(`*.test.ts`)。
- **目录结构**:见第 3.2 节;新增来源 = 在 `src/core/session-sources.ts` 加一个描述符对象(不改分支逻辑);新增检索工具 = 在 `src/agent/tools.ts` 加一个五元组(name/description/JSON Schema/zod/execute)。
- **宪法约束**(全文见 `.specify/memory/constitution.md`):新增依赖必须先修订白名单;文档与注释全中文;测试只用 fixtures/内存库/mkdtemp,绝不触碰真实 Agent 目录。
- **原版对照**:`main-1.0/`(AgentRecall v1 原版应用)仅作本地阅读对照,已在 `.gitignore` 声明、不入库。
- **接入真实 LLM**:`src/agent/llm.ts` 提供 OpenAI 兼容实现 `createOpenAiProvider({ baseUrl, apiKey, model })`;把 `runAgent` 的 `llm` 换成它即可(评测默认 MockLlm,真实 API 不进 CI)。

## 11. 常见问题(FAQ)

| 现象 | 原因与处理 |
| --- | --- |
| `DatabaseSync is not defined` / `node:sqlite` 不可用 | Node < 22.13;升级 Node 后重试 |
| `node src/cli.ts` 报 `ERR_MODULE_NOT_FOUND` | 源码不能直跑,用 `npm run cli` |
| 中文两字词搜不到 | 已内置:≥3 字符走 FTS5 trigram,<3 字符自动走 LIKE 兜底;仍搜不到先确认词确实在消息里 |
| Windows 终端中文乱码 | `chcp 65001` 或用 VSCode 内置终端 |
| server 报「找不到数据库路径」 | 先运行 `npm run cli` 并 `sync` 一次(生成 `~/.mini-recall/db-path`),或设 `MINI_RECALL_DB` |
| 目录下出现 `-wal` / `-shm` 文件 | WAL 正常产物,进程正常退出即回收,勿手工删运行中的 |
