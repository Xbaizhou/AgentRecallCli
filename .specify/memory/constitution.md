# mini-recall 项目宪法

> 本项目为 AgentRecall v1 的复现式学习仓库(mini-recall):领域内核 + 会话检索 Agent + MCP 对外暴露 + 评测闭环。
> 本宪法约束一切规格(spec)、计划(plan)、任务(tasks)与代码产出。

## 核心原则

### I. 全中文文档

所有面向人的文档必须使用中文书写,包括:规格说明、实现计划、任务清单、README、PROJECT-RECAP 总结、ADR 决策记录与本宪法自身的后续修订。代码内标识符(类型名、函数名、变量名)使用英文以符合工程惯例,代码注释使用中文(见原则 III)。
理由:项目目标是中文环境下的知识复盘与面试讲解,文档语言统一为中文可避免知识回顾中的二次翻译损耗。

### II. 代码简洁 (YAGNI)

每个模块必须只解决当前阶段明确提出的问题;禁止投机性抽象,禁止为「将来可能」预留的实现分支。简化实现是默认选项:如会话加载器取约 150 行的简化版而非复刻原版 3500 行,但抽象接口必须与原版对齐、扩展点保留。禁止上帝文件:任何单文件不得承载多层职责(原版 3186 行的 App.tsx 是明确的反面对照)。
理由:复现式学习项目里,代码可读、可逐条讲清「为什么这样设计」比功能堆砌更有价值。

### III. 基础注释

每个源文件顶部必须有一行职责说明。非自明的关键逻辑必须写「为什么」注释,重点位置:增量判定(size+mtime)、WAL 并发、FTS5 内容同步、Agent 停止条件、契约校验边界。注释必须使用中文,并随代码同步演进;禁止无信息量的复述式注释与过时注释。
理由:注释是面试讲解的直接素材,也是设计决策「为什么」的可追溯记录。

### IV. 最少第三方依赖

优先使用 Node 内置能力(node:sqlite、node:worker_threads、node:fs、node:path)。新增任何白名单之外的依赖,必须先以修订案形式更新本宪法并说明理由。依赖白名单:

- 运行时:zod(跨边界契约校验)。
- 开发期:TypeScript、Vitest(测试)、esbuild(仅用于 MCP 零依赖 bundle)。

MCP server 的打包产物必须零运行时依赖(单文件 CJS,`node` 直接运行,不 import 应用源码)。
理由:依赖树是复杂度与供应链风险的来源;原仓库「零依赖 MCP server」是明确的设计哲学,复现项目应贯彻同一约束。

### V. 质量门禁

`tsc --noEmit` 是唯一静态门禁,每次提交前必跑且必须全绿;`npm test`(Vitest)必须全绿,测试文件(`*.test.ts`)与源码同目录。每阶段必须通过其验收标准(含可运行演示与可量化数据)才允许进入下一阶段,禁止「回头再修」。Agent 相关测试必须用 MockLlm 脚本化驱动,保证 0 token 成本可进 CI;真实 LLM API 只允许通过 eval 命令手动触发。
理由:阶段式学习依赖稳定的基线;门禁全绿是「前一阶段产出 = 后一阶段依赖」的信任基础。

### VI. 数据安全红线(不可协商)

任何代码与测试绝对禁止读写真实的 `~/.claude`、`~/.codex` 及其他真实 Agent 会话目录。涉及文件系统的测试必须使用 `mkdtemp` 临时目录 + 合成 fixtures(必须包含正常、半行损坏、空文件三类样例)。MCP server 必须以只读模式打开 SQLite 数据库。fixtures 必须为手写合成数据,禁止将真实会话内容(即使脱敏)提交进仓库用于测试。
理由:会话数据含用户隐私,一次误写即不可逆;本红线与原仓库 `AGENT_RECALL_TEST_HOME` 的安全约定一脉相承。

### VII. 分层架构与纯函数边界

- 来源发现必须用「注册表 + 描述符」模式:新增来源只增加一个描述对象,不改已有分支;能力开关(capabilities)驱动上层行为,禁止 `if (source === "...")` 式散落判断。
- 格式适配器必须是纯函数(文本进、领域对象出),不碰文件系统;文件系统访问只允许 session-loader 一个模块。
- 一切跨边界调用(CLI→core、Agent→工具、MCP→查询)必须经 zod 契约层校验后执行;模型输出与外部输入一律视为不可信数据。
- core 必须不感知 CLI / Agent / MCP 等渲染与编排层,保证领域内核可被任意宿主复用。
理由:分层与边界是本项目面试可追溯性的核心论据,也是各阶段产出能够被复用的结构前提。

## 工程约束与技术栈

- 运行时:Node ≥ 22.13(`node:sqlite` 的 `DatabaseSync` 依赖此版本)。
- 模块:纯 ESM(`package.json` 声明 `"type": "module"`);`tsconfig.json` 必须 `strict: true`、`module: NodeNext`、`target: ES2023`。
- 导入:全仓禁止路径别名,import 一律相对路径;NodeNext 下引用本地文件必须带 `.js` 后缀。
- 目录结构固定为:
  - `src/core/` 领域内核(类型、来源注册表、格式适配、会话加载、存储、增量索引、查询);
  - `src/shared/` zod 契约层;
  - `src/agent/` 决策循环、工具注册表、查询改写、结果反思;
  - `src/mcp/` MCP server;`scripts/` 构建脚本;
  - `src/cli.ts` REPL 入口(扮演渲染层角色);
  - `fixtures/` 合成会话数据;`eval/` 评测数据集与 harness;`docs/PROJECT-RECAP.md` 项目总结。
- 数据库:SQLite(WAL 模式)+ FTS5 全文索引;迁移采用无编号自描述式(`CREATE TABLE IF NOT EXISTS` + `addColumnIfMissing` + 已执行迁移登记表),不引入编号迁移框架。

## 开发工作流与验收

- 阶段推进:阶段 0(跑通原版+建立基线)→ 1(领域内核)→ 2(存储与增量索引)→ 3(查询服务+契约层+CLI)→ 4(Agent 决策循环)→ 5(MCP 化)→ 6(评测闭环+项目总结)。前一阶段的产出是后一阶段的依赖,禁止跳阶段。
- 每阶段验收必须同时包含:可运行演示、可量化数据(如增量索引第二次同步输出 `indexed: 0, skipped: N`、FTS5 vs LIKE 耗时对比、A/B/C 检索模式 recall@5 对比表)、以及注册表/契约的不变量测试。
- 横切动作:每阶段结束写一条 ADR(背景 / 备选方案 / 决策 / 理由与代价 / 状态);每周进行一次「一次请求怎么穿越系统」的 15 分钟讲解彩排。
- 诚实原则:评测与对比数据必须如实记录,包括系统表现差的场景;与工业级原版的差距清单(简化假设是什么)必须诚实维护。
- 合规核对:阶段验收与自查时逐条对照核心原则;违反数据安全红线(原则 VI)的变更必须直接拒绝。

## 治理

- 本宪法是 mini-recall 项目一切工程决策的最高依据;规格、计划、任务与代码评审必须与本宪法保持一致。学习计划文档(`docs/mini_agent_lab/AgentRecall复现式学习计划.md`)提供阶段路线与实现细节;当路线与本宪法冲突时,以本宪法为准并记录差异。
- 修订流程:提出修订 → 说明动机与影响面 → 更新本文档并重写顶部同步影响报告 → 按语义化版本递增:新增原则或实质性扩展 = MINOR;仅措辞澄清 = PATCH;删除或重定义原则 = MAJOR。
- 合规审查:每阶段验收与每次代码评审必须核对核心原则;任何与数据安全红线(原则 VI)冲突的实现不得合入。
- 运行时开发指引以规格与计划文档为准;当其未覆盖时,以本宪法兜底。
